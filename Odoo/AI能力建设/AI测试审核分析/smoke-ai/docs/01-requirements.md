## 4.1 项目目标

每日冒烟任务结束后：

```text
接收结果
  → 校验证据完整性
  → 检索历史问题
  → AI 复核
  → 规则校验
  → 创建或关联问题
  → 更新用例复核结果
  → 汇总特性结果
  → 生成结构化报告
  → 发布或进入人工确认
```

## 4.2 首期范围

建议首期包括：

- 一种测试框架适配器。
- 一个真实 AI Agent 适配器，以及一个测试用 Fake Agent。
- Odoo 用例结果、复核记录、问题库、特性汇总、报告。
- MCP 业务工具。
- Windows 结果采集与断网补传。
- AI 分析 Worker。
- 历史问题精确匹配与人工确认知识复用。
- 人工复核和纠正入口。
- 权限、幂等、重试、审计。

## 4.3 首期不包括

- 自动重新刷机。
- 自动重启设备。
- AI 任意执行 Windows 命令或 ADB shell。
- 自动修改产品代码。
- 自动定位到某条提交并断言其为根因。
- 多 Agent 自主协作系统。
- 为所有日志建设向量数据库。
- 用 AI 重写现有任务下发平台。

后续有明确收益再扩展，避免一个人维护过多基础设施。

## 4.4 验收原则

- 原始测试结果不可被 AI 覆盖。
- 每个失败复核结论必须可追溯到证据。
- 证据不足时允许输出“不确定”。
- AI 故障不能阻断原有冒烟执行和人工发布流程。
- 更换 Agent 不修改 Odoo 业务模型。
- 更换测试框架不修改分析核心。
- 相同请求重复投递不能重复创建业务结果。
- 人工确认结果不能被迟到的 AI 结果覆盖。
