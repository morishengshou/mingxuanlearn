**简单说：越界读取是“读到了不该读的地方”；踩内存通常是“把不该改的内存改坏了”。** 两者相关，但不是同义词。“踩内存”是口语，交流时最好明确是在说非法读，还是非法写。

## 1. 核心区别

| 对比项 | 越界读取 | 踩内存（通常含义） |
|---|---|---|
| 关注点 | 读取超出对象或缓冲区边界的数据 | 错误写入导致内存内容被破坏 |
| 典型操作 | `x = a[n]`，其中 `n` 已越界 | `a[n] = x`，其中 `n` 已越界 |
| 是否直接改坏被访问的内存 | 单纯的读操作不会直接覆盖它 | 写操作可能覆盖其他数据 |
| 可能后果 | 读到错误数据、泄露信息、崩溃 | 变量或指针被改坏、程序行为异常、崩溃 |

这里的读写区别，对应正式分类中的“越界读”和“越界写”；两者都可能造成严重问题。([cwe.mitre.org](https://cwe.mitre.org/data/definitions/125.html))

例如，下面两行**分别看待**：

```cpp
int a[3] = {10, 20, 30};

int x = a[3];  // 越界读：合法下标只有 0、1、2
a[3] = 99;     // 越界写：典型的“踩内存”
```

越界写可能破坏相邻数据，但**不能保证 `a[3]` 恰好对应某个其他变量**，也不能保证越界读只是“读到一个随机数”；越界访问可能产生未定义或不可预期的结果。([cwe.mitre.org](https://cwe.mitre.org/data/definitions/125.html))

## 2. 它们有什么联系？

### 越界写是踩内存的常见原因，但不是唯一原因

例如，通过已经释放的指针写入，也可能破坏内存。这是**释放后使用（use-after-free）**，重点是对象生命周期已经结束，不一定表现为数组下标越界。([cwe.mitre.org](https://cwe.mitre.org/data/definitions/416.html))

```cpp
int* p = new int(10);
delete p;

*p = 20;  // 释放后写入，也可能“踩内存”
```

### 越界读和踩内存可以出现在同一条故障链中

例如，可以有这样的因果关系：

```text
错误写入把长度字段改坏
        ↓
后续代码相信这个错误长度
        ↓
读取超出缓冲区范围的数据
```

反过来，越界读取得的错误值如果随后被当作下标或长度使用，也可能进一步引发错误写入。这里是故障链的示意，并不意味着每次越界读都会导致踩内存；未正确验证的长度和下标正是越界访问的重要成因。([cwe.mitre.org](https://cwe.mitre.org/data/definitions/125.html))

## 3. 排查时怎么区分？

如果使用 AddressSanitizer，重点看报错中的：

- **`READ of size ...`**：发生了非法读取。
- **`WRITE of size ...`**：发生了非法写入。

不要只看到 `heap-buffer-overflow` 就认定是越界写：这个错误类别也可能由越界读触发。ASan 可以检测堆、栈和全局对象上的越界访问，以及释放后使用等问题。([clang.llvm.org](https://clang.llvm.org/docs/AddressSanitizer.html?utm_source=openai))

**记忆方式：越界读强调“读过界”，踩内存强调“写坏了”；排查时把操作类型、边界和对象生命周期分开看。**
