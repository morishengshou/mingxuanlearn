# C++ 符号表怎么“解”出来？

你说的"解符号表"通常指两件事：**① 把符号表 dump 出来看**，**② 把 `_ZN3foo3barEi` 这种乱码还原成人类能读的函数签名（demangle，解修饰）**。下面从工具用法讲到手工解码规则。

---

## 一、为什么 C++ 符号是"乱码"

C++ 支持函数重载、命名空间、模板、类成员，但链接器只认一个扁平的字符串名字。所以编译器会把
命名空间 + 类名 + 函数名 + 参数类型 编码进一个符号里，这叫 **name mangling（名字修饰）**。

```cpp
int add(int, int);        // → _Z3addii
int add(double, double);  // → _Z3adddd
extern "C" int add2(int); // → add2   (C 链接，不 mangle)
```

这也是为什么 `extern "C"` 能让 C 代码调用 C++ 函数。

## 二、把符号表 dump 出来（Linux / GCC / Clang）

```bash
g++ -g -c main.cpp -o main.o      # 先编译出 .o
```

### 1. `nm` —— 最常用

```bash
nm main.o                # 原始符号
nm -C main.o             # -C = --demangle，直接解出可读名字（最常用！）
nm -C --defined-only main.o   # 只看本文件定义的符号
nm -C -u main.o          # 只看未定义（undefined）的符号 —— 查链接错误神器
nm -C -D libfoo.so       # -D/--dynamic 看动态库的动态符号表
nm -C -l main.o          # 附带源码行号（需要 -g）
nm -C --size-sort -S a.out    # 按符号大小排序，找体积大户
```

输出示例：

```
0000000000000000 T add(int, int)
                 U printf
0000000000000012 T main
```

中间那个字母是**符号类型**，很重要：

| 字母 | 含义 |
|---|---|
| `T` / `t` | 代码段函数（大写=全局，小写=文件内 static） |
| `D` / `d` | 已初始化的全局变量 |
| `B` / `b` | 未初始化全局变量（.bss） |
| `R` / `r` | 只读数据（常量、字符串） |
| `U` | **未定义**，需要别的目标文件/库提供 |
| `W` / `V` | 弱符号（inline 函数、模板实例常见） |
| `i` / `n` | 特殊段 / 调试信息 |

### 2. `c++filt` —— 单独解一个符号

拿到编译器报错里的乱码，直接扔给它：

```bash
$ echo '_ZNK2ns1A3fooEdPc' | c++filt
ns::A::foo(double, char*) const

$ c++filt _Z3addii _Z3adddd
add(int, int)
add(double, double)
```

还能当过滤器用，把整段日志里的符号全部替换掉：

```bash
./a.out 2>&1 | c++filt          # 解 crash 日志里的符号
cat link_error.log | c++filt
```

### 3. `objdump` / `readelf` —— 更详细

```bash
objdump -t main.o          # 静态符号表 (.symtab)
objdump -T libfoo.so       # 动态符号表 (.dynsym)
objdump -tC main.o         # 加 -C 解修饰
objdump -dC main.o         # 反汇编 + 解修饰（看汇编时很爽）
objdump -RC libfoo.so      # 重定位/PLT 表

readelf -sW a.out          # -s 符号表，-W 宽格式不截断
readelf --dyn-syms libfoo.so
readelf -d libfoo.so       # 依赖的 so、SONAME
```

`readelf -sW` 会给出 Bind（GLOBAL/LOCAL/WEAK）、Vis（DEFAULT/HIDDEN）等信息，排查"符号被 hidden 了导致找不到"时必用。

## 三、其他平台

| 平台 | dump 符号 | demangle |
|---|---|---|
| **macOS** | `nm -m a.out`、`objdump`、`dyld_info`、`otool -Iv` | `c++filt`、`swift demangle`(Swift) |
| **Windows MSVC** | `dumpbin /symbols foo.obj`、`dumpbin /exports foo.dll` | `undname.exe ?add@@YAHHH@Z` |
| **跨平台** | `llvm-nm`、`llvm-objdump`、`llvm-readelf` | `llvm-cxxfilt` |

注意：MSVC 用的是**完全不同的一套 mangling 方案**（形如 `?add@@YAHHH@Z`），`c++filt` 解不了，必须用 `undname`；反之 `llvm-cxxfilt` 两种都支持。

## 四、程序里动态 demangle（写 backtrace 用）

```cpp
#include <cxxabi.h>
#include <cstdlib>
#include <memory>
#include <string>

std::string demangle(const char* name) {
    int status = 0;
    // 返回的内存需要 free
    std::unique_ptr<char, void(*)(void*)> p{
        abi::__cxa_demangle(name, nullptr, nullptr, &status), std::free};
    return (status == 0 && p) ? p.get() : name;   // 失败就返回原名
}
```

配合 `<execinfo.h>` 的 `backtrace` / `backtrace_symbols` 就能打印可读的调用栈（编译时记得加 `-g -rdynamic`）。

## 五、手工解码 Itanium ABI 规则（面试/看日志时救命）

以 `_ZNK2ns1A3fooEdPc` 为例，从左往右扫：

```
_Z          C++ 修饰符号的固定开头
N ... E     嵌套名字（有命名空间/类作用域时出现）
K           const 成员函数（V=volatile, R=&限定, O=&&限定）
2ns         长度2 + "ns"   → 命名空间 ns
1A          长度1 + "A"    → 类 A
3foo        长度3 + "foo"  → 函数 foo
E           嵌套结束，后面开始是参数列表
d           double
Pc          P=pointer, c=char → char*
```
→ `ns::A::foo(double, char*) const`

**基础类型速查表：**

| 码 | 类型 | 码 | 类型 |
|---|---|---|---|
| `v` | void | `i` | int |
| `b` | bool | `j` | unsigned int |
| `c` | char | `l` | long |
| `a` | signed char | `m` | unsigned long |
| `h` | unsigned char | `x` | long long |
| `s` | short | `y` | unsigned long long |
| `t` | unsigned short | `f` | float |
| `w` | wchar_t | `d` | double |

**修饰前缀：** `P`指针 `R`左值引用 `O`右值引用 `K`const `V`volatile `A_`数组 `M`成员指针
（组合从右往左读：`PKc` = `const char*`）

**其他常见前缀：**

| 前缀 | 含义 |
|---|---|
| `_ZTV` | vtable（虚函数表） |
| `_ZTI` / `_ZTS` | typeinfo / typeinfo name（RTTI） |
| `_ZTh` / `_ZThn8_` | thunk（多重继承调整 this） |
| `_ZN...C1E` / `C2E` | 构造函数（complete / base object） |
| `_ZN...D0E`/`D1E`/`D2E` | 析构函数（deleting / complete / base） |
| `_GLOBAL__sub_I_xxx` | 全局对象的静态初始化函数 |
| `St` | `std::` 的缩写 |
| `S_` `S0_` `S1_` | **替换引用**，指代前面出现过的类型（压缩用） |
| `I ... E` | 模板参数列表 |

所以 `std::string` 会展开成一长串：
`NSt7__cxx1112basic_stringIcSt11char_traitsIcESaIcEEE`
（`std::__cxx11::basic_string<char, std::char_traits<char>, std::allocator<char>>`）——看到这种别慌，直接 `c++filt`。

## 六、新手最常用的实战场景

### 场景 1：`undefined reference to 'foo(int)'`

```bash
# 1. 谁需要它？
nm -C -u main.o | grep foo
# 2. 哪个库/目标文件提供它？
nm -C --defined-only libmylib.a | grep foo
# 3. 遍历所有 so 找符号
for f in /usr/lib/x86_64-linux-gnu/*.so; do nm -DC "$f" 2>/dev/null | grep -q ' T .*foo' && echo "$f"; done
```

常见原因：
- 只声明没定义 / 忘了把 .cpp 加进编译
- **链接顺序错**：`g++ main.o -lmylib`（库要放在使用者后面）
- C/C++ 混用忘了 `extern "C" { ... }`（对比 mangle 前后名字就能确认）
- 声明和定义签名不一致（少了个 `const`，符号就完全不同）
- ABI 不匹配：老库编译时 `_GLIBCXX_USE_CXX11_ABI=0`，符号里没有 `__cxx11`

### 场景 2：检查 so 到底导出了什么

```bash
nm -DC --defined-only libfoo.so | grep ' T '
readelf -sW libfoo.so | grep GLOBAL | grep -v UND
```

### 场景 3：crash 日志/汇编看不懂

```bash
./a.out 2>&1 | c++filt              # 解栈符号
addr2line -e a.out -fCi 0x401136    # 地址 → 文件:行号（-C 自动 demangle）
```

### 场景 4：想看编译器给某个函数生成的符号名

```bash
g++ -S main.cpp -o - | grep -E '^_Z'
# 或直接看编译产物
echo 'namespace ns{struct A{int f(double,char*)const;};} int ns::A::f(double,char*)const{return 0;}' \
  | g++ -x c++ -c - -o /tmp/t.o && nm /tmp/t.o
```

## 七、小提醒

- **`strip` 过的程序没有 `.symtab`**，`nm` 会报 "no symbols"，此时只能看 `.dynsym`（`nm -D`）。发布时保留一份带符号的原始文件或 `.debug` 文件用于事后分析。
- Mangling 方案**不属于 C++ 标准**，是各 ABI 各自定义的（GCC/Clang 用 Itanium C++ ABI，MSVC 自己一套），所以不同编译器的 .o/.lib 一般不能互相链接。
- 记不住规则完全没关系——**日常 99% 的情况只需要 `nm -C` 和 `c++filt` 两条命令**，手工解码只在没工具的环境或想深入理解时才需要。
